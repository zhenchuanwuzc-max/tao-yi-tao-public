# 「真问题筛选」极简纵表设计

日期：2026-07-16

## 目标

把「对味」配方库 → 框架中的「真问题筛选」，从“卡片列表 → 打开独立编辑页”改成类似 Excel 的极简纵向表格。

每个问题是一张两列表：左列是字段名，右列直接填写。多个问题从上到下排列，不使用横向大宽表，不需要横向滚动。现有「行业分析（天时·地利·人和）」及两条旧行业判断记录保持原样。

## 列表与新增

「真问题筛选」区域顶部只保留：

- 标题与一句说明；
- 当前问题数；
- 「+ 新增问题」按钮。

点击新增后，在现有问题上方插入一张空白纵表。新问题尚未保存时只存在于当前页面，不立即写入数据仓。

多个问题按 `updated_at` 从新到旧纵向排列。视觉采用已确认的 B 版：白底、细灰线、左列浅灰底、仅使用一条紫色强调线；不使用大面积紫色表头或分区色块。

## 单个问题的纵表字段

问题标题显示在表格顶部，并作为第一项可编辑内容。表格字段按以下顺序固定：

1. 提出日期：日期输入，默认当天；
2. 不解决的真实后果：多行文本；
3. 根因还是表象：下拉 `根因 / 表象 / 暂不确定`；
4. 当前时机：下拉 `现在解决 / 稍后解决 / 无需解决 / 待判断`；
5. 事实证据：多行文本；
6. 对话证伪：多行文本，同时记录聊了谁、排除了什么错误前提；
7. 下一步最小验证：多行文本；
8. 验证截止日：日期输入；
9. 结论：下拉 `真问题 / 待验证 / 假问题`；
10. 一句话理由：多行文本。

结论用少量文字颜色区分：真问题红、待验证橙、假问题绿；不铺满整行色块。

## 操作方式

每张已保存纵表底部提供：

- 删除：保留二次确认；
- 让 Claude 判断：使用当前表格内容生成提示词并复制；
- 保存：显式写入，填写过程不自动保存。

新建但未保存的纵表底部使用「取消 / 让 Claude 判断 / 保存」。取消只移除页面草稿，不访问删除接口。

保存规则：

- 问题标题不能为空；
- 其余字段允许留空，方便先记录问题、之后逐步补证据；
- 保存成功后显示服务端 `updated_at`；
- 保存失败时保留页面内填写内容，并显示现有失败提示，不清空草稿。

「让 Claude 判断」不强制先保存，直接读取当前单元格内容生成提示词。提示词仍要求只从「真问题 / 待验证 / 假问题」中选择一个结论，并给出最小验证动作。

## 数据结构

继续复用现有 `/frameworks` API 和 `data.json.frameworks`，不新增后端集合。

真问题记录使用：

```json
{
  "fwId": "fw_true_question",
  "fwVersion": 3,
  "title": "这个项目是否值得继续投入？",
  "raisedAt": "2026-07-16",
  "answers": {
    "impact": "...",
    "root": "根因",
    "timing": "现在解决",
    "evidence": "...",
    "dialogue": "...",
    "experiment": "..."
  },
  "deadline": "2026-07-23",
  "verdict": "待验证",
  "reason": "..."
}
```

`id / created_at / updated_at` 仍由服务端生成。当前数据仓没有 `fw_true_question` 历史记录，因此不需要数据迁移。

## 组件边界

- `renderFrameworks()`：继续负责整个框架页；行业分析沿用现有卡片与编辑器。
- `renderTrueQuestionSection(fw)`：只渲染真问题区域、空白草稿和纵表列表。
- `trueQuestionBodyFromRow(row)`：从一张纵表收集并清洗保存载荷。
- `saveTrueQuestion(row)`：按有无 `id` 调用 POST 或 PATCH，成功后更新本地数组并重渲染。
- `trueQuestionPrompt(fw, body)`：从当前表格内容生成判断提示词，不依赖已保存状态。

不拆分新的前端文件，避免为单页零构建项目引入额外加载或发布复杂度。

## 验收

1. 框架页中，行业分析展示与历史记录完全不变。
2. 真问题筛选以极简纵向双列表呈现，不出现横向滚动。
3. 点击新增出现空白纵表，取消不写数据。
4. 标题为空时不能保存；填写后 POST 成功并出现更新时间。
5. 编辑已保存问题后，只有点击保存才 PATCH；刷新页面可读回更新内容。
6. 三类下拉项值正确，结论文字色正确。
7. 「让 Claude 判断」能读取未保存的当前输入并生成完整提示词。
8. 删除已保存问题需要确认并调用 DELETE。
9. 保存失败不清空用户当前输入。
10. 桌面窗口与窄屏均保持单列纵表，字段名与输入区不截断。

## 范围边界

本次不重做行业分析框架，不增加自动保存，不新增统计图表，不修改后端同步机制，也不导入刚生成的 Excel 文件。
