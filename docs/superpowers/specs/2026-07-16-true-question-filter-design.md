# 「真问题筛选」框架设计

日期：2026-07-16

## 目标

在「对味」APP 的配方库 → 框架中，新增第二张内置卡片「真问题筛选」。每条记录对应一个待判断的问题，通过事实、后果、根因、时机、对话证伪和最小验证六个角度，最终归为「真问题 / 待验证 / 假问题」。

原有「行业分析（天时·地利·人和）」及其历史战场判断保持不变。

## 交互设计

框架列表展示两张卡：

1. 行业分析（现状不变）。
2. 真问题筛选：说明文案为「把困惑放进问题池，用事实与对话排除假问题」。

每张框架卡各自提供新建按钮，避免当前全局「+ 新建战场判断」只能创建行业分析记录的问题。真问题筛选的新建按钮为「+ 新建问题判断」。

打开真问题筛选记录后填写：

1. 如果不解决，会产生什么真实后果？
2. 它是根因，还是表象？
3. 它现在值得解决吗？
4. 有什么事实支持它确实存在？
5. 和谁聊过？对话排除了哪些错误前提？
6. 下一步最小验证动作是什么？

记录标题使用问题本体，例如「我是否需要换部门？」。保存后可继续编辑，也可生成判断提示词交给 Claude。结论枚举为「真问题 / 待验证 / 假问题」，并保留一句话理由。

## 实现方式

- 在前端 `BUILTIN_FW` 中新增 `fw_true_question`，沿用现有 `layers/questions` 结构。
- 为框架定义补充界面文案、结论枚举和提示词生成配置；行业分析使用原有文案与「重仓 / 观望 / 撤损」，新框架使用问题筛选文案与「真问题 / 待验证 / 假问题」。
- 新建动作从全局固定创建 `fw_industry`，调整为由对应框架卡传入 `fwId`。
- 快照仍通过现有 `/frameworks` 接口写入 `data.json.frameworks`，继续使用 `fwId` 区分框架，不新增后端集合，不改历史数据。
- 提升 `FW_VERSION`，仅用于解释新保存记录的结构；旧记录仍按自身 `fwId` 和已存答案读取。

## 判断提示词

提示词要求 Claude：

- 区分事实与主观担忧；
- 检查问题是否有真实后果、是否只是表象、是否值得现在处理；
- 把尚未验证的命题留在「待验证」，不强行二分真假；
- 指出对话已经排除的错误前提；
- 给出一个最小验证动作；
- 最后只从「真问题 / 待验证 / 假问题」中选择一个结论。

## 兼容与错误处理

- 旧的行业分析记录无须迁移，列表、打开、编辑和判断能力保持原样。
- 找不到 `fwId` 时不渲染损坏的编辑页，并回到框架列表给出提示。
- 保存仍复用现有 API 失败提示；不直接修改数据仓文件。

## 验收

1. 框架列表同时出现「行业分析」和「真问题筛选」。
2. 两张卡的新建按钮分别创建正确类型的记录。
3. 真问题筛选显示六问，能保存、重新打开、编辑和删除。
4. 真问题筛选只能选择「真问题 / 待验证 / 假问题」。
5. 生成的提示词包含六问答案和问题筛选规则。
6. 现有两条 GGS 金物流记录仍能正常打开，结论仍为「重仓 / 观望 / 撤损」。
7. 页面刷新后新记录仍存在，`/health` 与 `/data` 返回正常。

## 范围边界

本次不新增通用框架编辑器，不改变数据同步机制，不重构现有话术配方，也不把课堂里关于认知健康的表达作为医学结论写入框架。
